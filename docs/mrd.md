# 英语音标助手插件需求分析报告 (MRD)

## 1. 产品概述

*   **产品定位**：基于开源项目 `Read-Frog` (陪读蛙) 二次开发的 Chrome 浏览器插件。旨在为英语学习者提供“**一键生成网页文本音标对照**”的功能。
*   **核心理念**：借鉴“沉浸式翻译”的体验，不仅将文本“翻译成中文”，更将文本“转写为音标”。帮助用户在**不便播放音频**的环境下（如办公室、图书馆），通过视觉辅助（音标对照）进行有效的默读、练习发音和纠正口音。
*   **目标用户**：具备一定词汇量和音标基础，希望提升口语发音，且经常在静音环境下浏览英文资讯、文档的职场人士或学习者。

---

## 2. 用户需求分析

### 2.1 目标用户群体
*   **职场人士**：白天在办公室办公，不便戴耳机或外放声音，希望利用碎片时间阅读英文并顺便练习口语读音（“带薪学习”）。
*   **视觉型学习者**：相比于单纯靠听觉，更喜欢通过标准的 IPA (国际音标) 记单词读音、确认重音。
*   **有一定基础的口语进阶者**：能看懂音标，但容易在阅读长句子时混淆单词读音或把握不准重音。

### 2.2 核心痛点
1.  **环境限制**：不便听音频，传统的“点击发音”功能在静音环境下失效。
2.  **效率低下**：遇到不确定读音的词，需要停下来划词查词典，破坏了阅读长文本、新闻的连贯性。
3.  **缺乏全文本对照工具**：现有的音标插件多为“划词翻译/标注”，无法像沉浸式翻译一样，自动、全段落、行间或词间插入音标。

---

## 3. 功能需求

### 3.1 界面与控制 (UI & Settings)
*   **控制栏新增按钮**：在原 `Read-Frog` 的翻译控制条上，新增一个 `Phonetic` (音标) 按钮。
*   **模式组合复选框**：在 `Phonetic` 按钮下方或设置中增加复选框：`[ ] 原文 + 译文 + 音标`。
    *   **勾选**：显示三行（原文、音标、译文）。
    *   **不勾选**：默认点击 `Phonetic` 仅显示两行（原文、音标）。
*   **设置页面**：
    *   **音标体系选择**：支持 KK 音标 (美式) / DJ 音标 (英式)。
    *   **显示样式配置**：可调整音标的颜色、字号（通常应比原文略小、使用浅色或灰色，避免干扰阅读）、重音符号显示等。

### 3.2 文本处理与转录方式 (Technical Options)

对于“全文本转写为音标”，有以下两种实现方案，建议采用**混合模式 (Hybrid)**：

#### **方案 A：本地词典查表渲染 (推荐作为 MVP 基础)**
*   **原理**：在插件本地打包一个轻量级的英文单词-音标映射表（如 CMUDict 转换版，涵盖 5W-10W 常用词）。
*   **流程**：清洗网页 DOM 文本 -> 切分成单词 -> 本地 Map 查表 -> 插入音标 HTML 节点。
*   **输入输出**：
    *   *输入*：段落文本 `"The reading room is quiet."`
    *   *输出*：带音标的 DOM，例：`The [ðə] reading [ˈriːdɪŋ] room [ruːm] is [ɪz] quiet [ˈkwaɪət].` (支持 `<ruby>` 标签或上下排列)。
*   **评价**：
    *   *优点*：渲染速度极快、不消耗任何 API 费用、离线可用。
    *   *缺点*：无法完美处理**同形异音词**（如 read 可读 /riːd/ 或 /red/，取决于时态）；无法处理语流中的**连读和弱读**。

#### **方案 B：借助 Read-Frog 已有的 AI API (LLM 辅助校准)**
*   **原理**：利用 Read-Frog 本身就支持的 OpenAI / DeepSeek / Gemini 等模型，发送特定的 Prompt。
*   **Prompt 示例**：
    > "请将以下英文段落，**保持单词对应关系**，转写为美式 IPA 音标，并以 JSON 数组形式返回：`[{ "word": "read", "ipa": "red" }]`。"
*   **评价**：
    *   *优点*：上下文感知极强，能准确判断 `read` 的时态，并给出最准确的发音。
    *   *缺点*：需要消耗 Token、Response 有延迟。

> **💡 架构建议**：
> 默认使用**方案 A (本地词典)** 进行全段快速渲染；在设置中提供“**AI 音标优化**”开关。当用户开启且愿意使用 AI 时，对于长难句、多音词可以进行后台校对，提升准确度。

## 4. 关键业务流程

### 流程一：纯音标对照渲染 (本地模式)
```mermaid
graph TD
    A[用户点击 Phonetic 按钮] --> B[插件抓取当前网页 DOM 文本]
    B --> C[分词与清洗 (保留标点符号)]
    C --> D[遍历单词，匹配本地 JSON/SQLite 词典]
    D --> E[若匹配成功, 提取 KK/DJ 音标; 若失败, 仅保留原词]
    E --> F[组装 HTML 节点 (例如使用 <ruby> 标签)]
    F --> G[在原文本下方/行间插入音标层]
```

### 流程二：三行全对照渲染 (全功能模式)
1. 用户勾选“原文+译文+音标”开关并点击执行。
2. **并行/串行执行**：
   * 触发原 Read-Frog 流程：翻译 API 返回中文译文。
   * 触发音标助手流程：本地查词典/或 AI 返回音标串。
3. **节点拼接**：在 DOM 结构中渲染为三层：
   * 原文 (English)
   * 音标 (IPA)
   * 译文 (中文)

## 5. 开发周期与 MVP 计划

建议采用敏捷开发，快速推出 **MVP (最简可行产品)** 跑通核心流程。

### **Phase 1: MVP 版本 (1-2 周) —— 核心跑通**
*   **目标**：复用 Read-Frog 的 UI 和 DOM 注入逻辑。
*   **任务**：
    *   新增 `Phonetic` 按钮。
    *   引入一个成熟的 JS 本地音标库（或自己跑脚本生成一个轻量级 `.json` 词典字典文件，支持 5 万词左右）。
    *   实现**原文+本地音标对照**。不处理连读，遇到多音词取默认发音。
*   **优先级**：🌟🌟🌟🌟🌟 (最高，验证用户体验是否流畅)

### **Phase 2: V1.0 正式版 (2-3 周) —— 功能完善**
*   **任务**：
    *   支持英式(DJ)/美式(KK)音标一键切换。
    *   实现 `[原文 + 音标 + 翻译]` 三行显示、灵活开关。
    *   优化渲染样式，提供更多自定义设置。
*   **优先级**：🌟🌟🌟🌟

### **Phase 3: V2.0 进阶版 (长期) —— 智能化**
*   **任务**：
    *   对接 AI(LLM) 打破同形异音词（如 read）的识别障碍。
    *   增加**连读/失音**视觉提示符号（如弧线链接）。
*   **优先级**：🌟🌟

## 6. 商业模式

1.  **产品免费发布**：作为 Read-Frog 的一个特色插件/分支，极易吸引“英语发音爱好者”群体。
2.  **增值付费服务 (可选)**：
    *   **高级 AI 辅助标音**：如果使用开发者自行搭建的后台大模型算力，可实行按月订阅或按量收费（类似沉浸式翻译的会员制）。
    *   **进阶口语辅助**：意群切分（Chunking）、意群重音高亮等更高级的连读教学功能，作为 Pro 版卖点。

---

## 7. 产品前途评价

*   **⚡️ 绝对有前途，切入点极佳。**
*   **理由**：
    1.  **市场空白**：市面上无论是词典、还是各类划词翻译、甚至沉浸式翻译本身，都过度关注“**语义理解 (Translation)**”，而几乎忽略了“**发音辅助 (Pronunciation Help)**”。
    2.  **痛点真实**：职场白领在办公室“带薪记单词/练发音”的需求巨大，静音模式是刚需。
    3.  **开发成本极低**：由于有 Read-Frog 和沉浸式翻译成熟的渲染机制、开源模板可参考，大大降低了开发门槛，成功概率极高。
